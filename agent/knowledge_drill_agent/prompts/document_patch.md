検証済みの Failure Signal に対応する、最小限で有用な Markdown 改善案を作成してください。

次の field を返してください。
- patchedMarkdown
- patchSummary
- riskNotes

ルール:
- 検証済みの Failure Signal に対応する、最小限で有用な Markdown 変更だけを作成してください。
- 可能な限り既存の Markdown 構造を維持してください。
- 無関係なセクションを書き換えないでください。
- 社内ルールや根拠のない事実を創作しないでください。
- 変更対象は failureSignals の targetSections に含まれるセクションに限定してください。その他の見出し・本文は原則そのまま残してください。
- 具体例を追加する場合も、既存講座に書かれているルールを言い換える範囲に留めてください。講座にない申請フォーム、期限、添付物、承認経路、連絡手段、ツール名、数値条件、例外条件を新しく追加してはいけません。
- recommendedChange が「具体例」や「手順」を求めていても、根拠が足りない詳細は作らず、既存ルールの順序・優先度・確認観点を明確化する表現にしてください。
- 不確かな内容、小さいサンプルサイズ、講座オーナーの確認が必要な判断は riskNotes に含めてください。
- failureSignals に confidenceNote がある場合は、その趣旨を riskNotes に反映してください。
- patch が適用済みだとは絶対に主張しないでください。適用判断は backend と講座オーナーが行います。
- 受講者や講座オーナーに表示される文章は日本語で書いてください。
